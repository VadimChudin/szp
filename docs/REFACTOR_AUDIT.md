# SZP: аудит и первый этап рефакторинга

База: f70a3be, локальные исходники v6.0.2. Это НЕ подтверждение состояния установленного терминала.

## Математика текущего построения
- zone_detector.extract_wick_levels: экстремумы значимых теней свечей (порог 30% диапазона).
- cluster_levels: сортировка цен, присоединение к текущему кластеру при расстоянии от его медианы не более CLUSTER_TOLERANCE (по умолчанию $5).
- adaptive_zone_width: средний True Range последних ATR_PERIOD свечей основного таймфрейма, умноженный на ATR_MULTIPLIER, с ограничениями ширины. Центр и ширина дают top/bottom.
- Балл: веса таймфреймов с >=2 касаниями плюс отдельные бонусы объёма, круглой цены, FVG; возможны POC/HVN при включённом источнике.
- После первичного отбора есть дополнительное объединение центров с расстоянием <=3*CLUSTER_TOLERANCE (обычно $15). Центр перемещается по весу числа касаний, ширина остаётся detected_width. Это может сливать отдельные диапазоны; последствия требуют проверки на истории. Балл при этом не пересчитывается по объединённым доказательствам.
- active_zones добавляет фильтры состояния/удалённости, сохраняет снимок и применяет общий лимит. По умолчанию MAX_ZONES_ON_CHART=6; отдельный лимит индикатора MaxZonesToDraw=6. Это максимумы, а не требование показать шесть. Жёсткого текущего лимита 3 не установлено.
- Балл S не является вероятностью отскока. Tick volume сам по себе не доказывает присутствие крупного игрока.

## Подтверждённые препятствия проверке
Все python_core/data/XAUUSD_{M1,H1,H4,D1}.csv целиком состоят из NUL-байтов. Рабочие файлы совпадают с HEAD. Эти данные непригодны для backtest; цифры доходности не рассчитывались.
В этой сессии нет скриншота текущего терминала, живого zones_output.json и журнала. Причина именно трёх видимых зон у пользователя не установлена.

## Исправлено в исходниках
Оба индикатора MT4/MT5:
- дополнительные контуры диапазонов top/bottom (ShowZoneBounds), без заливки, центр сохранён;
- подписи основного уровня используют цвет текста графика;
- отступ подписи вычисляется из масштаба графика в пикселях и от границы диапазона;
- изменение масштаба/темы вызывает обновление;
- подпись MT4 больше не привязана к +12 будущим свечам;
- валидный пустой массив [] очищает старые зоны вместо игнорирования.
Python: явная ошибка DataUnavailableError для пустого или NUL-заполненного заголовка CSV, сохранена поддержка UTF16.
Добавлены проверки контракта исходников MQL и тесты CSV. Они НЕ заменяют компиляцию и визуальные испытания MetaTrader.

## Что пока НЕ исправлено / не подтверждено
- Пересечения подписей очень близких уровней: нужен полноценный алгоритм размещения и проверка в терминале.
- Парсер JSON остаётся строковым, не полноценным структурным парсером.
- Соответствие готовых ex4/ex5 исходникам не проверено. deploy_component предпочитает бинарник, если он уже лежит рядом.
- Текущее объединение/оценка зон и фильтры алгоритма НЕ изменялись: нельзя подменять аудит произвольным повышением числа линий.
- Не проводилась компиляция MetaEditor, сборка EXE или установка у пользователя.
- Существующие ex4/ex5 НЕ обновлены: их нельзя выдавать за результат этого рефакторинга.

## Следующий контрольный этап
Нужны MT4/MT5, версия индикатора, screenshot, текущий zones_output.json и пригодная OHLC-история. Затем: трассировка числа кандидатов после каждого фильтра, проверка закрытых свечей и времён, walk-forward с учётом спреда/проскальзывания, частоты пробоев, MAE/MFE, drawdown и ожидания на отдельном периоде. Зона — область интереса, не безусловная команда входа.

## Установка этого этапа
Архив содержит изменённые исходники/тесты, НЕ установщик. Не запускать штатное развёртывание как способ обновления этих правок: рядом остаются прежние бинарники. Требуется перекомпилировать изменённые .mq4/.mq5 в соответствующем MetaEditor, проверить журнал компиляции, подключить полученный индикатор на демо-график и проверить светлую/тёмную тему, зум, [] и обычный JSON. До этой проверки не использовать изменения как основание для сделок.
