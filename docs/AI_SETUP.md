# Подключение ИИ: как это работает и как выпускать ключи

## Что делает ИИ, а что нет

Модель — надстройка над готовым индикатором, а не второй алгоритм.

| Кто | За что отвечает |
|---|---|
| `zone_detector` | цена зоны, ширина, структурный score |
| `persistent_zones` | окно показа k × ATR(H1) |
| `zone_confirmation` | вердикт LIVE / WATCH / DEAD |
| `broker_normalize` | эталон Dukascopy и сдвиг на цену брокера |
| **`ai/annotator`** | **ранжирование зон и подпись одной фразой** |

Модель не может изменить цену зоны даже теоретически: в грамматике ответа
(`ai/zone_note.gbnf`) нет поля цены, а ограничение действует на уровне
декодера, а не на уровне просьбы в промпте. Она заполняет только
`ai_verdict`, `ai_note` и `ai_rank`.

Причина такого разделения: канон «одинаковые зоны у всех брокеров» держится на
детекторе и эталоне Dukascopy. Языковая модель недетерминирована — доверь ей
геометрию, и два запуска дали бы разные линии.

## Первая настройка (один раз)

```
cd python_core
python -m ai.keygen init
```

Команда создаёт `szp_signing_key.txt` и печатает строку с публичным ключом.
Вставьте её в `ai/licensing.py`:

```python
PUBLIC_KEY_HEX = "e1b3c14d..."
```

Про приватный ключ:

- **сделайте резервную копию** — потеря означает, что все выпущенные ключи
  перестанут выпускаться (проверяться будут по-прежнему), и придётся менять
  публичный ключ в сборке;
- **никому не передавайте** — утечка позволяет выпускать ключи самому;
- он уже в `.gitignore`, в репозиторий не попадёт;
- `ai/keygen.py` исключён из сборки (`excludes` в spec), клиенту не уезжает.

## Выпуск ключа клиенту

1. Клиент нажимает **Qwen** в футпринте и присылает код своей машины —
   29 символов вида `DN4XQ-0PP69-9Y56D-P750G-GENMP-0DDR`.

2. Выпускаете ключ:

```
python -m ai.keygen issue --code DN4XQ-0PP69-... --days 3
python -m ai.keygen issue --code DN4XQ-0PP69-... --days 30
python -m ai.keygen issue --code DN4XQ-0PP69-... --forever
python -m ai.keygen issue --days 30 --unbound      # без привязки к машине
```

3. Проверить перед отправкой:

```
python -m ai.keygen check --token SZP1-...
```

4. Клиент вставляет ключ в поле и нажимает «Активировать», затем «Скачать
   модель».

## Что происходит у клиента

Профиль компьютера показывается **до** оплаты и до скачивания, чтобы не было
«купил, а не работает»:

| Железо | Модель | Качать | Глубина разбора |
|---|---|---|---|
| ≥24 ГБ VRAM | Qwen3 32B | 20 ГБ | полный: цепочки инструментов, аналоги |
| 12–23 ГБ VRAM | Qwen3 14B | 8.4 ГБ | полный |
| 8–11 ГБ VRAM | Qwen3 8B | 4.7 ГБ | стандартный |
| 6–7 ГБ VRAM | Qwen3 4B | 2.5 ГБ | базовый: подписи и ранжирование |
| 4–5 ГБ VRAM | 4B или 1.7B | 1.4–2.5 ГБ | базовый / ограниченный |
| без GPU, ≥32 ГБ RAM | Qwen3 14B | 8.4 ГБ | полный, на процессоре |
| без GPU, ≥16 ГБ RAM | Qwen3 8B | 4.7 ГБ | стандартный, на процессоре |
| без GPU, ≥8 ГБ RAM | Qwen3 4B | 2.5 ГБ | базовый |
| <8 ГБ RAM | недоступно | — | сообщается до продажи ключа |

Модель вызывается раз в закрытую свечу H4 — 6 раз в сутки. Латентность не
важна, поэтому берётся самая крупная модель, какую тянет железо, а не самая
быстрая.

Загрузка идёт с докачкой: обрыв на 8-м гигабайте не заставляет качать заново.

## Срок действия

Три барьера против «вечной триалки»:

1. `exp` внутри подписи — в файле не поправить;
2. `last_seen` — максимальное виденное время, хранится с HMAC;
3. время последней свечи Dukascopy — внешний якорь, локально не открутить.

Действующее время = максимум из трёх. Перевод часов назад просто не влияет на
расчёт. Истёк ключ — ИИ отключается сам, индикатор работает в обычном режиме.
Файл модели остаётся: продлил ключ — работает сразу, качать заново не нужно.

## Привязка к железу: 2 из 3

Отпечаток собирается из machine GUID, серийника системного диска и модели CPU.
Достаточно совпадения двух. Жёсткая привязка ко всем трём ломала бы лицензию
при замене диска — это поток жалоб вместо защиты.

## Честность статистики

Инструмент `historical_analog` считает, сколько раз цена исторически заходила
в полосу зоны и чем это заканчивалось. Та же процедура прогоняется по случайным
уровням, и результат отдаётся с двусторонним z-тестом.

Если зона не лучше случайного уровня или касаний меньше восьми — инструмент
сообщает об этом прямо, и модели запрещено выдавать такую статистику за
подтверждение. Процент без базы сравнения — анекдот, а не сигнал.

## Про окна консоли

Весь запуск дочерних процессов идёт через `proc_util` (CREATE_NO_WINDOW плюс
скрытый STARTUPINFO). Это касается футпринта, настроек, патчера терминалов и
`llama-server`. Раньше патчер вызывал metaeditor для каждого найденного
терминала напрямую, и окна выскакивали десятками.

Тест `tests/test_no_console_windows.py` не даёт регрессии вернуться: прямой
вызов `subprocess` вне `proc_util` роняет сборку.

## Ограничения, которые стоит знать

Подпись Ed25519 подделать нельзя, но пропатчить проверку в бинаре — можно, как
в любом клиентском софте. Схема защищает от передачи ключа знакомым и от
бесконечной триалки, но не от реверс-инженера. Вкладываться в обфускацию
сверх этого смысла нет.
